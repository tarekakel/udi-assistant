# When a new UDI-DI is required (EU MDR 2017/745, Annex VI Part C, section 3.9)

## Changes that trigger a new UDI-DI
A new UDI-DI is required whenever there is a change that could lead to misidentification of the device or ambiguity in its traceability. In particular, a new UDI-DI is required for a change of: the name or trade name; the device version or model; whether the device is labelled as single use; whether it is packaged sterile; the need for sterilisation before use; the quantity of devices provided in a package; or critical warnings or contra-indications.

## Changes that do not trigger a new UDI-DI
Changes that do not affect the identification of the device model, such as a corrected address of the manufacturer or an updated contact detail, do not require a new UDI-DI. Such data elements are updated in the UDI database within 30 days of the change, keeping the existing UDI-DI.

## Software
For software, a new UDI-DI is required whenever there is a modification that changes the original performance, the safety or the intended use of the software, or the interpretation of data. Minor software revisions, such as bug fixes, usability enhancements that are not for safety purposes or security patches, require a new UDI-PI but not a new UDI-DI.

## Packaging levels
Each packaging level (unit of use, inner box, case) has its own UDI-DI. Changing the number of devices in a package therefore requires a new UDI-DI for that packaging level, because the quantity per package is one of the attributes that defines the identifier.
